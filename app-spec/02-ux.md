# 02 — UX/UI behavior

## Workspace

Top toolbar: project title/dirty indicator, Open, Save, source/target languages, model selector, Run, Cancel, Export. Left rail: model runs and status. Main area: source editor plus output split tree. Collapsible bottom tray: block list, progress and diagnostics. Empty state gives three steps: paste text, connect local server, choose model.

Initial layout: source left, one model output right. “Add model” selects provider/model and creates a new run/output pane. Pane menu uses unambiguous labels: **Place beside** (left/right), **Place above/below** (stacked), **Close view**, **Reopen view**. A vertical divider produces side-by-side editors; a horizontal divider produces stacked editors. Labels describe placement instead of relying on ambiguous split terminology.

Each output header shows model name, settings summary, completed/total, status, Cancel model, Retry failed, and menu. Each block has a gutter badge and source counterpart. No output is padded with artificial blank lines to align lengths.

## Editor contract

Source is one continuous editor with block boundary decorations. Each model pane is a continuous block-aware editor, with protected separators and editable successful block regions; implementation may virtualize block editor instances. Copy/export omits visual separators and badges. Each block keeps exact generated text; user-edited text is a separate current version. Ordinary newline and paragraph editing inside a region is allowed; crossing a protected boundary cannot merge block identities. Select-all/copy/search traverse the pane; undo history is scoped to the edited block.

Streaming region is read-only and marked “Draft”; successful regions remain editable while other blocks run. After Run, source is locked to the snapshot with an **Edit source** action. That action opens an editable new revision; old results remain available. Running translations continue against the frozen revision. Running the changed source requires explicit activation of the new revision after the old job ends/cancels; no mixed-revision display.

## Alignment and navigation

Block-linked scrolling is enabled by default: the top visible block ID and relative fraction inside it determine target panes' position, clamped to available content. Pointer/keyboard interaction identifies the driving pane and prevents feedback loops. Disable linked scrolling independently. Clicking a block badge focuses/highlights the counterpart; missing output displays its status. Source line numbers and block IDs are separate concepts.

## Dynamic changes

- Adding a model during a job queues its blocks for the active snapshot; show its captured settings and queue position.
- Closing a pane only changes layout. Its run continues and appears in the rail; results can be reopened.
- Removing a model run is a separate action: cancel its pending work and archive its results; restore is available. Permanent deletion is a distinct confirmation.
- Last source view cannot be closed. At least one visible view remains; closed outputs need not remain visible.
- Split divider minimum pane size: 240 px width/160 px height. At narrower windows use pane tabs; retain the saved tree for restoration. Reset layout is always available.

## Progress and controls

Block badges: Pending, Waiting, Translating, Done, Needs review, Failed, Canceled, Stale. A stream draft does not count as Done. Overall shows terminal blocks/total and successful blocks/total; individual counts distinguish failures and cancellations. Do not show a token-derived percentage as completion. Optional ETA appears only after three successful blocks and is marked approximate.

Cancel immediately stops dispatch within its scope (block, model, or job), aborts the current client request when applicable, and preserves drafts marked incomplete. Block cancellation allows later blocks to proceed with source-only context; model cancellation allows the next model to proceed; job cancellation stops the whole queue. It does not claim server-side generation has stopped. Retry appends an attempt and generates a candidate; if a successful/manual version exists, user chooses **Use candidate** or **Keep current**. Retrying a block marks later blocks of that same run stale because their context may now differ. Offer **Retranslate downstream**; preserve existing versions.

## Saving and exporting

Save As chooses `.ltw.json`; Save updates it atomically. Autosave is a separate local recovery copy, not a replacement for Save. On reopen show recovery when it is newer than the saved file. Export selects revision/models and current edited versus original generated text (current by default). Missing/failed/stale blocks are listed in preview. Partial export requires explicit **Export partial** and inserts labeled gap markers; comparison CSV includes status columns. Plain text exports one model; Markdown can export one or several labeled model sections; CSV has source and output/status columns per model. Export never launches inference.

## Accessibility and feedback

Keyboard-operable toolbar, rail, block navigation and dividers; visible focus; screen-reader status announcements throttled to state changes; status uses text/icons as well as color. Ctrl/Cmd+S saves; Ctrl/Cmd+Enter runs; Escape closes dialogs, never cancels work implicitly. Connection failure appears next to provider setup with endpoint and recovery steps. Source with only whitespace and zero selected models disable Run with inline explanation. Unsaved close offers Save/Discard/Cancel; active jobs additionally offer Cancel and close or Keep working.
